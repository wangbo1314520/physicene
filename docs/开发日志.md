### 关键技术决策与踩坑

- **Java 枚举 vs MySQL ENUM 大小写**：DDL 枚举按设计文档是小写（'student'），Java enum 是大写（STUDENT），
  `@Enumerated(STRING)` 读回直接炸。解法：三个 `AttributeConverter`（Role/Source/Status）做大小写映射，
  DDL 保持设计文档原样不动。
- **JDBC URL 字符集**：`characterEncoding=utf8mb4` 不是合法 Java 字符集名（UnsupportedCharsetException），
  应写 `UTF-8` + `connectionCollation=utf8mb4_unicode_ci`。
- **删除场景 FK 约束**：场景有实验记录时 DELETE 被 FK 挡住（500）。解法：@Transactional 内先
  deleteByScenarioId 清记录再删场景（符合 SRS 5.5 学生数据随场景删除）。
- **vue-router 5 地址栏不更新**：登录后 router.push 组件已切换但地址栏停在 /login（且 E2E 的
  wait_for_url glob `**/lab` 恰好匹配 `/login?redirect=/lab` 造成假通过）。解法：登录成功用整页
  location.href 跳转；E2E 改为等组件选择器而非 URL。
- **Vite 模块缓存不刷新（第三次出现）**：编辑 .ts 模块（threeScene/composable）后 HMR 偶发不下发新代码，
  浏览器拿到新旧混合模块静默崩溃。已列入检查清单：**改完非 .vue 模块必须 curl 验证下发内容或直接重启 Vite**。
- **Playwright 与 HTML5 DnD**：drag_and_drop 与 draggable 组件兼容性差，用合成 DragEvent
  （DataTransfer + clientX/Y）直测 drop 处理器。
- **本机 MySQL 8.0 vs 文档 8.4**：开发期用本机 8.0（root/123456），JSON 列/窗口函数全兼容；
  部署时仍按设计走 Docker mysql:8.4。

### 关键技术决策与踩坑

- **dyn4j 5.x 包结构与 4.x 不同**：World 在 `org.dyn4j.world`（非 dynamics）；监听器注册用
  `addCollisionListener`（非 addListener）；Vector2 模长是 `getMagnitude()`（非 magnitude()）。
  通过 jar 反编译（javap）逐个探明后编码，一次编译通过率大幅提升。
- **step(1) 语义**：实测确认每调用一次推进一个 1/60s 步，与契约 timestep 一致（自由落体 60 帧=1s 验证）。
- **碰撞去重**：碰撞持续期 ManifoldCollisionData 每步回调，用 pair Set 去重只报首次。
- **前端 TS 7 不兼容**：pnpm 默认装了 TypeScript 7（原生重写版），vue-tsc 报
  `ERR_PACKAGE_PATH_NOT_EXPORTED`；锁定 `typescript@~5.9.0` 解决。
- **E2E 时序**：帧只在运行中推送，测试脚本必须"run 后立刻连 WS"（分两次 curl 会错过整场仿真）。
