## 2. 架构：只做三件事（策划书 §二）

| 策划书要求 | 实现 | 位置 |
|:--|:--|:--|
| 元件面板 + 拖拽搭建界面 | 元件目录 **89 项**（力学 24 / 电磁 30 / 热学 10 / 光学 12 / 近代 8 / 通用 6），每项含可调参数规格 + 识别标签；拖拽/点击加入、画布内拖动、连线模式（绳/杆/导线拓扑）、属性面板实时调参、撤销/重做/复制/删除/清空、本机保存列表、JSON 导入导出、PNG 导出、维度由元件自动判定（纯 2D/2.5D/3D 画布风格随之变化） | `frontend/src/sandbox/catalog.ts`、`SandboxView.vue` |
| 通用场景求解器 | **场景识别器**：58 条规则按“需要的元件标签集合”匹配，取命中最多者，把元件参数映射为求解器参数，然后**内嵌对应引擎运行**：① 62 个高考/竞赛场景定义（`MechScene` 2D/2.5D、`EMScene` 3D，真实物理逐步积分 + 多过程时间轴 + 临界事件 + 能量条 + 讲解模板）② 3 个独立场景组件（板块 / 平抛+圆周 / 加速→筛选→磁场）③ 电路元件组合 → `CircuitEditor`（节点电压法 + 相量，自由连线 + 故障检测）④ 兜底：方块/小球/斜面/墙/场的任意组合 → 交接到刚体实验台 `/lab`（Java dyn4j）⑤ α 散射 → 教材实验直达。识别失败时给出“再加哪个元件就能成为哪个场景”的建议 | `recognizer.ts` |
| 自由搭建 AI 助手 | 四种模式：分析（只识别）/ 提示（思路要点 + 规律 + 临界，不给答案）/ 讲解（过程 / 受力 / 推导 / 数值 / 易错 / 同类 / 竞赛）/ 变式（画布改参数即时重算理论结果）；模板与高考层讲解器同源；「AI 完整讲题」「分析运行结果」与自由问答走真 AI（`aiAgent.ts` → Java 代理 → Python DeepSeek + 教材知识库），带场景上下文（识别结果、元件参数、最近读数），离线自动回退到模板 | `SandboxAi.vue` |

数据面板（`SandboxData.vue`）：运行器每次「记录」/ 跑到结束自动入表，自动从读数与事件文本解析数值字段（t、参数、x_m、v、Q…），自选 x/y 字段一键导出到坐标纸（`GraphPaper`：描点 / 拟合 / 残差），CSV 导出。

**设计取舍（诚实说明）**：自由搭建不是“任意元件组合的通用微分方程求解器”（策划书 §十二 也把“元件组合爆炸”列为首要风险），而是“元件组合 → 已验证的专用求解器”的映射：凡是映射到 62 个场景定义的组合，物理与讲解都是真实且经 E2E 与解析解比对过的；刚体类任意组合仍有 dyn4j 通解；电路任意连线有 MNA 通解。组合外的元件（传感器、图像、能量条等显示类）不影响求解，识别卡会明确列出“未参与本求解的元件”。

## 5. 已知限制

1. 组合识别是“最像的一条规则”：同一批元件若同时满足多条规则，取需要标签最多的一条；识别卡与 AI 助手会显示未参与求解的元件与“再加什么就能成为什么”的建议。
2. 服务器端场景持久化与多端同步未做（本机 localStorage + JSON 文件）。
3. 运行控制无单步/回放；3D 画面 PNG 导出受 WebGL 缓冲限制。
4. 电路类组合在沙盒画布只做拓扑识别，真正的端子连线在内嵌的电路编辑器里完成。
