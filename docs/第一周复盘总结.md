## 一、遇到的问题（按"现象 → 原因 → 解决"复盘）

### 问题 1：Python 3.12 新版本安装包 404

- **现象**：python.org 和华为云镜像上 `python-3.12.14-amd64.exe` 均返回 404，下载到的只有几百字节的 HTML 错误页。
- **原因**：Python 3.12 自 3.12.8 起进入**安全维护期**，官方不再发布二进制安装包，只发源码。目录列表里能看到版本号不代表有 exe。
- **解决**：改用 3.12 系列最后一个带官方 Windows 安装包的 **3.12.7**（2024-10 发布）。对毕设而言补丁版本差异无关紧要，大版本锁 3.12 才是 V5 验证项的要求。
- **教训**：装"文档指定版本"前先确认该版本是否存在对应平台的安装产物，别假设最新补丁一定有安装包。

### 问题 2：Poetry 启动撞上 Windows 商店 python 假别名

- **现象**：`poetry install` 直接失败，报 `Command ['C:\Users\...\WindowsApps\python.EXE', ...] returned non-zero exit status 9009`。
- **原因**：Poetry 启动时会探测 PATH 里的 `python`。本机 PATH 中 WindowsApps 的 Store 别名排在真实 Python 之前，而这个别名不是可用的解释器（9009 = 找不到命令）。
- **解决**：不动系统环境变量（本项目的安装铁律），在**单条命令内**把 3.12 临时前置：`export PATH="/e/Program/Python312:$PATH" && poetry ...`。此后 Poetry 一切正常。
- **教训**：Windows 上多 Python 并存时，工具链探测 `python` 的结果不可预期；用命令级 PATH 覆盖比改全局变量安全得多。

### 问题 3：Jackson 3 包名变更导致编译失败（本周最有价值的坑）

- **现象**：`PingWebSocketHandler` 里 `import com.fasterxml.jackson.databind.ObjectMapper` 编译报"程序包不存在"。
- **原因**：**Spring Boot 4 默认 JSON 库从 Jackson 2 换成了 Jackson 3**，坐标变为 `tools.jackson.core:jackson-databind:3.1.4`，Java 包名从 `com.fasterxml.jackson` 改为 `tools.jackson`。Boot 4 的 starter 里根本不带旧包。
- **解决**：改 import 为 `tools.jackson.databind.ObjectMapper`。顺带发现 Jackson 3 的序列化异常改为 **unchecked**（JacksonException extends RuntimeException），catch 策略相应从 `catch (IOException)` 放宽为 `catch (Exception)`。
- **教训/后续影响**：⚠️ 第四周 Python 契约联调、第三周 JPA JSON 列处理时，所有涉及 Jackson 的代码都要按 Jackson 3 的 API 写；网上搜到的 Jackson 2 示例代码不能直接抄。`spring.jackson.deserialization.fail-on-unknown-properties` 这类配置项在新版下的实际归属也要届时实测。

### 问题 4：V6 兼容性风险实测（文档预告的最大坑，结果通过）

- **现象**：需求文档 SRS §7.5 V6 反复警告"Spring Cloud 低于 2025.1.2 与 Boot 4.1.0 启动即报错"。
- **实测结论**：Boot 4.1.0 + Spring Cloud **2025.1.2** 协同启动成功（5.5 秒），OpenFeign 调用 `/health` 正常转发。风险项关闭。
- **附带观察**：启动日志出现 `InetUtils: Cannot determine local hostname` 无害警告（本机主机名解析问题，不影响功能）；Feign 场景可忽略。

### 问题 5：Git Bash 与 Windows 原生程序的路径鸿沟

- **现象**：这一周多次小坑——`/tmp` 下的文件 node 读不到；`cmd //c mklink /J` 引号被 Git Bash 转义破坏报"文件名语法不正确"。
- **原因**：Git Bash 的 `/tmp` 是虚拟路径，Windows 原生程序（node/cmd）看不到；反斜杠加引号在两层 shell 间传递会被吃掉。
- **解决**：跨程序传文件统一用 `$USERPROFILE` 或项目绝对路径；建 junction 改用 PowerShell `New-Item -ItemType Junction`。
- **教训**：在 Windows 上做跨语言工具链联调，路径一律用双方都认识的写法（`E:\...` 或 `/e/...` 视消费方而定）。

### 问题 6：Node 24 vs 文档要求 Node 20

- **现象**：文档要求 Node 20，本机是 Node 24 + pnpm 11 + Vite 8。
- **实测结论**：向前兼容，无任何报错。风险项关闭，不做降级。
