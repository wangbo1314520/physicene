# 审查清单

用途： zcode 每轮交付前自跑。脚本能判的脚本判，脚本判不了的写进摘要给 Harness。
原则： 每一条对应一个历史坑。清单里有的，不许再犯。

## 0. 使用方式

```
zcode 交付前
  ├─ 跑 §1 硬门禁（脚本自动，必须全绿）
  ├─ 跑 §2 结构检查（zcode 自审，填进摘要）
  └─ 写 §3 摘要（只列"需要判断的"）
        ↓
  脚本判不过 → 退回 zcode 自己修，不叫 Harness
  脚本判过 + 摘要非空 → 升级 Harness
  全绿 + 摘要为空 → 直接进测点，不叫 Harness
```

## 2. 结构检查（zcode 自审，写进摘要）

### 2.1 DoD 对照

- □ 本轮 DoD 逐项列出
- □ 每项标：✅ 完成 / ⚠️ 部分 / ❌ 未做
- □ 部分/未做的，写清原因 + 回填时间点
- □ 不许"全部完成"一句话

### 2.2 断言质量（每条新断言）

| # | 检查 | 反例 |
|---|---|---|
| 2.2.1 | 是物理量，不是状态 | ❌ "no collision" / "无异常" / "运行完成" |
| 2.2.2 | 独立来源分级 | 物理独立 / 教材规律 / 方法独立 / 自洽检查 / 经验标定 |
| 2.2.3 | 容差有依据 | 解析估计×1.5 或 σ×3；不许"实测 12% 给 12%" |
| 2.2.4 | 不是公式复刻 | 断言值不能直接由被测函数算出 |
| 2.2.5 | E2E 验画布内容 | 不只验状态 |

### 2.3 归因质量（若本轮有归因）

归因闸门 6 条，缺一不可：

- □ 第 0 条：验证代码是否真在运行（curl + log）
- □ ① 复现 ≥3 次
- □ ② 参数扫描（随参数变=数值/物理；不变=环境/逻辑）
- □ ③ 反例排除
- □ ④ 原始数据存档
- □ ⑤ 失败项完整捕获（✗ 行保留）

缺任一项 → 归因作废，重新按序走。

### 2.4 参数链（若本轮新增参数）

- □ catalog 定义（key + 默认值）
- □ RunBridge 透传（表达式级，不是名字级）
- □ Java 消费（getOrDefault / param() 具体位置）
- □ 三处默认值一致

### 2.5 元件壳处理（若本轮新增元件）

- □ 物理是否实现？
- □ 未实现 → 显式拒绝（不许静默 wall）
- □ NO_BODY 归属（固定端 / 纯显示 / 检测器 / 虚设）
- □ 收录标准：已接线 / 纯显示 / 放置即警告

## 3. 摘要模板（给 Harness）

只写"需要判断的"，脚本判过的写一行带过。

```markdown
# 交付摘要 · 第 N 轮

## 提交
- commit：xxx
- 覆盖率：64/65 → 65/65（公式：65−1−0−0）

## 脚本判过（不需要 Harness 看）
- npm run verify ✓ / env-check 13/13 ✓ / PID 一致 ✓
- v2/v3/v4 ✓ / lint-migration 4 规则 ✓ / lint-events ✓

## 需要判断的（≤3 件）
1. 【归因】v=2.0020 是耦合结果还是直算？实验设计如下…
2. 【设计】photogate 放 P6 还是 P5b？判据…
3. 【新问题】NO_BODY 新增 2 元件，归类如下…

## 本轮遗留
- 无 / 清单
```

摘要 ≤ 1500 token。超过说明没筛干净。

## 4. 升级规则

| 情况 | 处理 |
|---|---|
| 脚本红 | 退回 zcode，不叫 Harness |
| 脚本绿 + 摘要空 | 直接进测点，不叫 Harness |
| 脚本绿 + 摘要 ≤3 件 | 升级 Harness |
| 摘要 >3 件 | 说明筛选不够，重新筛 |
| Harness 退回 | zcode 修，重跑 |
| Harness 和 zcode 僵持 | 人工介入 |

## 5. 审查结论库（缓存）

同类问题不重复问 Harness。

存 `docs/审查结论库.md`：

```markdown
## 半虚报
判据：commit 声称 vs diff 实际
结论：diff 没有 = 未做，不管 commit 怎么写
首次：假收紧（0.15 标签 vs 代码 0.15）

## 静默丢弃
判据：写了但没接线
结论：必须显式拒绝，不许静默
首次：heater（notes 从未上屏）
```

（每次 Harness 给出新结论 → 追加）
下次遇到同类 → 先查库 → 命中就不叫 Harness。
