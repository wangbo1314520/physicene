## 1. 引言

### 1.1 目的

本文档定义"AI Agent 智能物理实验平台"（项目代号 physicene）的需求规格，作为开发、测试、验收的依据。v3.0 在 v2.6 基础上完成产品定位升级——从"预设 3 种模拟"升级为"自由搭建场景 + 预设模板为辅"，并对 F2 物理引擎、F3 Agent、F4 OCR、技术栈、工程结构进行系统性重构。

### 1.2 范围

v1 实现范围：
- 学生端：自由搭建场景 / 加载模板 / 跑物理模拟 / 自然语言对话 / OCR 拍照建场景 / 自动生成报告 / 个性化引导
- 教师端：备课工具，配置教学策略 + 预览实验，不批改、不管理学生
- v2 预留扩展位：班级管理、多 Agent 协作、多模态、跨学科元件、3D 物理

### 1.3 术语定义

| 术语 | 定义 |

## 3. 功能需求

### F1 账号与登录

**目标**：区分学生/教师/admin 身份，数据归属到人。

**输入**：账号、密码、角色（student/teacher，admin 走 SQL 初始化）。

**输出**：JWT 令牌、用户画像初始化。

**流程**：
1. 注册（选 student 或 teacher 角色，role 在 Java Controller 层白名单校验，仅允许 student/teacher）
2. 登录 → 鉴权 → JWT 签发 → 角色路由到对应界面
3. 密码重置 v1 无前端页面，admin 直接连 MySQL 用 BCrypt 生成新 hash 覆盖
4. 首个 admin 通过 SQL 初始化脚本插入（`init.sql` 含一条 admin INSERT，BCrypt hash 手动生成）

**验收标准**：
- 注册 student/teacher 成功，注册 admin 被拒（返回 code=1001）
- 登录成功返回 JWT，登录失败返回 code=1002
- 未登录访问受保护接口返回 code=1002，前端跳 /login
- 越权访问返回 code=1003，前端跳 /403

**边界**：v1 不做第三方登录、不做邮箱验证、不做复杂权限树。

#### F2.0 统一接口契约（场景驱动）

```java
public interface Simulation {
    String getType();                              // 模拟类型
    ElementSchema getElementSchema();              // 支持的元件类型
    ValidationResult validate(Scene scene);         // 校验场景
    SimResult run(Scene scene);                     // 运行场景
    EstimateResult estimate(Scene scene);           // 估计时长
}

class Scene {
    String sceneId;                                 // v3.1 标注：创建请求时为空，后端生成后返回；前端 PUT/POST 不传 sceneId
    List<PhysicsElement> elements;                  // 元件列表（核心）
    SimulationConfig config;                        // 全局配置
}

// v3.2 新增：API 请求体 DTO（无 sceneId）
class SceneCreateRequest {
    List<PhysicsElement> elements;
    SimulationConfig config;
    String source;                                  // "manual" | "ocr" | "template"，可选
}

class SceneUpdateRequest {
    List<PhysicsElement> elements;
    SimulationConfig config;
}
// Scene 为响应体（含后端生成的 sceneId）

class PhysicsElement {
    String id;                                      // "cube_001"
    String type;                                    // cube/sphere/slope/track/spring/wall/point_charge/magnet
    Vector2D position;                              // 位置（x,y）
    double angle;                                   // 朝向角度
    Vector2D scale;                                 // 元件尺寸缩放倍数（相对基准尺寸），基准尺寸由 ElementBehavior 定义
    PhysicalProperties properties;                  // 物性（mass/friction/restitution/charge/bField/bDirection）
    InitialState initialState;                      // 初始运动状态（v3.1 新增：v0/direction 归并到 velocity 向量）
    boolean isFixed;                                // 是否固定
    boolean isVisible;                              // 是否可见
    String color;                                   // 颜色
}

class PhysicalProperties {
    double mass = 1.0;
    double friction = 0.0;
    double restitution = 0.5;
    double charge = 0.0;                            // 电磁元件用
    Double bField = null;                           // v3.3 新增：磁感应强度（T），magnet 专用；非磁体元件为 null
    String bDirection = null;                       // v3.3 新增："out"（垂直纸面向外）/"in"（垂直纸面向内），magnet 专用
}

class InitialState {
    Vector2D velocity = Vector2D.ZERO;               // 初速度向量（含大小和方向）
    double angularVelocity = 0.0;                    // 初角速度（可选）
}

class SimulationConfig {
    Vector2D gravity = new Vector2D(0, -9.8);        // v3.1 改为 Vector2D（dyn4j 重力有方向），默认朝下
    double timestep = 1.0/60;                       // 物理步长
    int maxFrames = 1800;                           // 最大帧数
    double maxDuration = 30.0;                      // 最大时长（秒）
    double stillThreshold = 2.0;                    // 静止超时（秒）
    boolean airResistance = false;                  // v3.2 新增：空气阻力开关（默认关闭）
    double dragCoeff = 0.1;                         // v3.2 新增：阻力系数（仅 airResistance=true 生效）
}

class Vector2D {
    double x, y;
    static final Vector2D ZERO = new Vector2D(0, 0);
}
```

**v3.1 字段统一说明**：原 F2.1/F2.2/F2.3 模板中的 `v0` 改为 `initialState.velocity` 的大小，`direction`/`angle` 合并进 `initialState.velocity` 向量方向；`gravity=0` → `gravity={x:0,y:0}`，`gravity=9.8` → `gravity={x:0,y:-9.8}`（朝下为负 y）。

**参数校验三层约束（随元件走，不集中维护）**：
- L1 类型与枚举：元件 type 在 ElementSchema 允许列表内
- L2 物理合理范围：每个属性 min/max/step 声明（mass>0 且 <1e6kg 等）
- L3 跨元件一致性：元件间关系校验（如"方块在斜面上"自动识别，不需要学生显式声明）

#### F2.1 小车碰撞模板（template_collision）

**定位变化**：从"唯一入口"降级为"快速开始模板"。学生点击模板 → 系统自动生成两个 cube + 地面 wall 的初始场景 → 学生可自由增删元件、修改参数。

**模板初始场景**：
- 元件 1：cube, position=(-3, 0), properties={mass:1, friction:0}, initialState={velocity:{x:5, y:0}}
- 元件 2：cube, position=(3, 0), properties={mass:1, friction:0}, initialState={velocity:{x:-5, y:0}}
- 元件 3：wall, position=(0, -0.5), scale=(20, 0.2)（地面）
- config: gravity={x:0, y:0}, maxDuration=10

**模板自带停止条件**（可被用户覆盖）：碰撞后两车分离超过初始距离 2 倍时停止，或 10 秒超时。

**验收标准**：加载模板后场景含 3 个元件，碰撞瞬间产生关键事件，动能-时间图在 e<1.0 时有损失可见。

---

#### F2.2 带电粒子磁场模板（template_charged_particle）

**模板初始场景**：
- 元件 1：point_charge, position=(0, 0), properties={mass:1.67e-27, charge:1.6e-19}, initialState={velocity:{x:1e5, y:0}}
- 元件 2：magnet, position=(0, 0), properties={bField:0.1, bDirection:"out"}
- config: gravity={x:0, y:0}

**模板自带停止条件**：T=2πm/(qB)，跑 min(5T, 10秒)，避免极小周期瞬间结束。电荷量 q=0 / 磁场 B=0 时 L2 拦截。

**物理表述修正**：v2.6 已把"点电荷磁场"改为"带电粒子在磁场中的运动"（洛伦兹力 F=qv×B），对应高中物理教材"磁场对运动电荷的作用"。

---

#### F2.3 斜抛运动模板（template_projectile）

**模板初始场景**：
- 元件 1：cube, position=(0, 0), properties={mass:0.1}, initialState={velocity:{x:14.14, y:14.14}}（v0=20, angle=45° 分解）
- 元件 2：wall, position=(0, -0.5)（地面）
- config: gravity={x:0, y:-9.8}, airResistance=false, dragCoeff:0.1

**模板自带停止条件**：y≤0 且 t>0 时停止（落地），或 30 秒超时。airResistance=false 时 dragCoeff 不生效（L3 警告，validate 时忽略）。

#### F2.4 模拟播放控制（暂停/单步/回放）

| 控制 | 行为 |
|---|---|
| 播放/暂停 | 实时模拟可随时暂停，暂停后可继续 |
| 单步 | 暂停状态下按一个物理步长推进一帧 |
| 回放 | 模拟跑完后拖时间轴到任意时刻重看 |
| 历史回看 | 历史实验记录可加载，重新拖动时间轴回看 |

**运行模式**：实时流式（边算边推帧）。模拟自然结束帧缓存整体保留不淘汰，超时运行（>30秒）才触发淘汰。

**验收标准**：暂停后改参数=新实验需重新跑（v1 不支持 resumeWith）；单步粒度固定为该模拟物理步长；回放是只读的。

#### F2.5 场景管理功能（新增）

**目标**：学生自由搭建场景，不限预设模板。

| 子功能 | 说明 |
|---|---|
| 元件库 | v1 提供 cube/sphere/slope/track/spring/wall 六种基础元件 |
| 拖拽放置 | 从元件库拖到画布，自由摆放位置和朝向 |
| 参数编辑 | 点击元件设置物理属性（质量、摩擦、弹性、电荷） |
| 场景保存 | 保存/加载场景（存 ExperimentScenario.scene_data） |
| 场景校验 | 后端 Simulation.validate() 自动识别元件间关系（碰撞检测自动处理"方块在斜面上"） |
| 场景清空 | 一键清空所有元件 |

**验收标准**：
- 拖拽元件到画布成功放置，位置和朝向正确
- 点击元件弹出参数编辑面板，修改后保存生效
- 场景保存到数据库，重新加载后元件完整恢复
- 场景含非法参数（如 mass≤0）时后端拒绝保存并返回结构化错误
- 清空场景后画布无元件，scene_data.elements 为空数组

**边界**：v1 不支持元件间约束关系显式声明（如"固定到"），靠物理引擎自动检测；v2 加约束关系。

**模板隔离**（v3.1 新增）：加载模板生成的是新场景实例（深拷贝），学生修改不影响原模板。模板本身只读，学生不可覆盖模板定义；学生保存的是基于模板派生的 ExperimentScenario（source=template），原模板 SimulationTemplate 配置由后端维护。

#### F2.6 元件系统扩展机制（新增）

**目标**：保证"加新元件只加不改"——新增元件只写一个 ElementBehavior 实现类 + 注册一条配置，不动既有代码。

**命名说明**（v3.1 修正）：F2.0 的 `PhysicsElement` 是数据类（DTO，描述元件是什么），F2.6 的元件行为接口改名为 `ElementBehavior`（描述元件怎么动）。两者职责正交、可同包共存，避免重名编译冲突。

```java
// 数据类（F2.0）：描述元件是什么
class PhysicsElement {
    String id;
    String type;
    Vector2D position;
    double angle;
    Vector2D scale;
    PhysicalProperties properties;
    InitialState initialState;
    boolean isFixed;
    boolean isVisible;
    String color;
}

// 行为接口（F2.6）：描述元件怎么动
public interface ElementBehavior {
    String getType();
    Body createBody(World world);                   // dyn4j Body 创建
    Vector2D computeForce(ElementContext ctx);       // 自定义力（如洛伦兹力）
    void updateState(Body body, double dt);          // 状态更新
}

public interface ElementBehaviorFactory {
    ElementBehavior create(Map<String, Object> params);
}

public class ElementRegistry {
    private static final Map<String, ElementBehaviorFactory> registry = new HashMap<>();
    public static void register(String type, ElementBehaviorFactory factory) { ... }
    public static ElementBehavior create(String type, Map<String, Object> params) { ... }
}
```

**元件版本规划**：
| 版本 | 元件 |
|---|---|
| v1.0 | cube, sphere, slope, track, spring, wall |
| v1.5 | point_charge, magnet, uniform_e_field, uniform_b_field |
| v2.0 | gas_piston, lens, light_ray |

**验收标准**：加新元件工作量 < 3 人日且不修改既有代码（强化 4.5 可扩展性约束）。

#### F2.7 SimResult 契约

```java
class SimResult {
    String simId;
    String type;
    Scene scene;                                    // 改为存完整场景（v2.6 是 params）
    double timestep;
    double totalDuration;
    List<Frame> frames;                             // 混合存储
    List<DataRow> dataTable;
    Map<String, ChartData> charts;
    List<KeyEvent> keyEvents;
    List<FrameIndex> frameIndex;
    CameraInfo camera;
}

class Frame {
    double t;
    Object snapshot;                                // FullSnapshot 或 KeySnapshot
    String snapshotType;                            // "full" | "key"
}

class CameraInfo {
    double cameraX, cameraY;
    double cameraZ;                                 // 新增：3D 视角 Z 高度
    double cameraAngle;                             // 新增：摄像机俯仰角（默认 45°）
    boolean followMode;
    String viewMode;                                // 新增："isometric"（默认2.5D）/"top_down"（纯2D）
}
```

**物理仍是 2D**（x/y 坐标），不加 z。2.5D 视觉由前端 Three.js 负责，cameraZ/cameraAngle/viewMode 由前端消费。

**帧缓存策略**：单次模拟最大 1800 帧（30s×60fps），自然结束保留不淘汰，超时运行环形缓冲淘汰最早帧+每 60 帧抽样保留 1 锚点。旧帧 KeySnapshot（轻量），最新 300 帧 FullSnapshot（完整）。

**FullSnapshot 字段按所含元件类型动态生成**（v3.1 修正：自由搭建场景可能混合多种元件，按元件类型组织而非按"场景类型"一刀切）：
- 含 cube/sphere/slope 等力学元件 → 输出 `{elements:[{id,x,y,vx,vy}], kineticEnergy, momentum}`
- 含 point_charge/magnet 等电磁元件 → 输出 `{elements:[...], radius, cycleCount}`
- 含抛体元件（带初始速度的 cube + 重力）→ 输出 `{elements:[...], maxHeight, range}`
- 混合场景：上述字段按元件分组并集输出，无数据的字段省略

**KeySnapshot 必含字段**：t、所有运动主体的 position(x,y)、velocity(vx,vy)。各模拟可扩展。

**持久化**：模拟结束整体序列化为 JSON 存 ExperimentRecord.sim_result。

**回放分页**：`GET /api/records/{id}?frameOffset=0&frameLimit=300`，响应头 X-Total-Frames / X-Total-Duration，首次请求返回 frameIndex 全局索引前端缓存。

#### F2.9 辅助类型定义（v3.3 新增）

**定位**：F2.0/F2.6/F2.7 引用的辅助类型此前只有名字没有字段定义。本节把它们全部补齐——这些类型是 Java↔Python 通信契约、前端回放/图表渲染的共同输入，也是 F4.2 结构化错误与 F2.7 帧快照的落地形态。Python 端 Pydantic 模型按本节字段名对齐，前端 TypeScript interface 可直接由本节生成。

**约定**：所有物理量用 SI 单位（见各字段注释）；可选字段用包装类型（`Double`/`Integer`）并允许 `null`，序列化时无数据的字段整体省略而非输出 `null`。

```java
// ========== 1. 元件 schema（F2.0 getElementSchema()，承载 L1/L2 校验）==========
class ElementSchema {
    List<String> allowedTypes;                      // 允许的元件类型列表（L1 白名单）
    Map<String, Map<String, PropertySpec>> propertySpecs;  // 元件类型 → (属性名 → 属性规范)
}

class PropertySpec {
    String name;                                    // 属性名，如 "mass"
    String type;                                    // "number" | "string" | "boolean"
    Double min, max, step;                          // L2 物理合理范围（type="number" 时有效）
    String unit;                                    // "kg" | "m/s" | "C" | "T" | "N"；无量纲为 null
    boolean required;                               // 是否必填（决定了前端表单是否可留空）
    Double defaultValue;                            // 前端表单默认值（如 magnet.bField 默认 0.1）
}

// ========== 2. 校验结果（F2.0 validate()，对应 6.4 code=1001 的 data）==========
class ValidationResult {
    boolean valid;                                  // 是否通过
    List<ValidationError> errors;                   // 结构化错误列表（null 时视为空列表）
}

class ValidationError {
    String field;                                   // 出错字段路径，如 "elements[0].properties.mass"
    String expected;                                // 期望，如 ">0"
    String actual;                                  // 实际值（字符串化后）
    String message;                                 // 面向学生的提示文案
    String level;                                   // "error"（拦截保存）| "warning"（仅提示，不拦截）
}
// level 的必要性：F2.3 规定 airResistance=false 时 dragCoeff 不生效属 L3 警告，
// validate 时必须能区分"致命错误（拦截 save）"与"可忽略警告（放行但提示）"。

// ========== 3. 时长估计（F2.0 estimate()，对应 GET /api/simulations/{type}/estimate）==========
class EstimateResult {
    double estimatedDuration;                       // 预估时长（秒），上限受 maxDuration 约束
    Double estimatedPeriod;                         // 预估周期（秒），仅周期运动（磁场圆周/弹簧振子）有值
    Integer estimatedFrames;                        // 预估帧数 = estimatedDuration / timestep
    String hint;                                    // 提示文案，如"周期过短，建议增大 B 或放大场景"；无提示为 null
}

// ========== 4. 力计算上下文（F2.6 ElementBehavior.computeForce()）==========
class ElementContext {
    List<PhysicsElement> allElements;               // 场景全部元件（只读，禁止在 computeForce 中修改）
    Map<String, Vector2D> positionMap;              // 元件 id → 当前位置
    Map<String, Vector2D> velocityMap;              // 元件 id → 当前速度（洛伦兹力 F=qv×B 依赖它）
    double currentTime;                             // 当前模拟时刻（秒）
    Vector2D gravity;                               // 全局重力（自定义力需先扣除重力时使用）
}

// ========== 5. 数据表行（SimResult.dataTable）==========
class DataRow {
    double t;                                       // 时刻（秒）
    Map<String, Double> fields;                     // 字段名 → 数值，如 {"v1":3.2, "v2":-1.8, "Ek":5.1}
}

// ========== 6. 图表数据（SimResult.charts，key 为图表类型）==========
class ChartData {
    String chartType;                               // 白名单："v-t" | "x-t" | "Ek-t" | "p-t" | "r-t"（对齐 F5）
    String xLabel;                                  // x 轴标签（含单位），如 "t / s"
    String yLabel;                                  // y 轴标签（含单位），如 "v / (m·s⁻¹)"
    List<Double> xData;
    List<Double> yData;
    List<KeyEvent> annotations;                     // 曲线标注点，复用 KeyEvent，供 F5"拖时间轴高亮当前点"定位
}

// ========== 7. 关键事件（SimResult.keyEvents，驱动 WebSocket {type:"keyEvent"}）==========
class KeyEvent {
    double t;                                       // 事件发生时刻（秒）
    String type;                                    // "collision" | "max_height" | "landing" | "launch" | "stop"
    String label;                                   // 前端显示文本，如"碰撞瞬间"
    Integer frameIndex;                             // 对应帧全局序号，回放定位用
}

// ========== 8. 帧全局索引（SimResult.frameIndex，回放分页）==========
class FrameIndex {
    int frameOffset;                                // 帧在本次模拟中的全局序号（0 起）
    double t;                                       // 该帧对应时刻（秒）
}
// 用法：GET /api/records/{id}?frameOffset=0&frameLimit=300 首次请求返回完整 frameIndex，
// 前端缓存后按需分页拉帧，无需重复请求索引。

// ========== 9. 完整快照（F2.7：最新 300 帧用 FullSnapshot）==========
class FullSnapshot {
    List<SubjectState> elements;                    // 所有运动主体的完整状态
    // —— 力学场景（含 cube/sphere/slope 等力学元件）——
    Double kineticEnergy;                           // 总动能 Ek（J）
    Double momentum;                                // 总动量 p（kg·m/s，矢量和取模）
    // —— 电磁场景（含 point_charge/magnet 等电磁元件）——
    Double radius;                                  // 轨道半径 r（m）；直线运动或速度与 B 夹角 <1° 时为 null
    Integer cycleCount;                             // 已完成周期数
    // —— 抛体场景（带初速度的 cube + 重力）——
    Double maxHeight;                               // 最大高度（m）
    Double range;                                   // 射程（m）
    // 混合场景：上述字段按实际所含元件类型取并集；无数据的字段整体省略
}

class SubjectState {
    String id;                                      // 元件 id，与 PhysicsElement.id 一致
    double x, y;                                    // 位置（m）
    double vx, vy;                                  // 速度（m/s）
    Double angle;                                   // 朝向（弧度），可选扩展，供前端 2.5D 渲染
}

// ========== 10. 轻量快照（F2.7：旧帧用 KeySnapshot）==========
class KeySnapshot {
    double t;                                       // 时刻（秒）
    List<SubjectState> subjects;                    // 仅位置+速度，不含能量/动量等派生量（保证旧帧体积小）
}
```

**与已定义类型的关系**：`CameraInfo` / `Frame` / `SimResult` / `Scene` / `PhysicsElement` 已在 F2.0 与 F2.7 定义，本节不重复。`Frame.snapshot` 是 `Object`，运行期按 `Frame.snapshotType` 反序列化为 `FullSnapshot`（"full"）或 `KeySnapshot`（"key"）。

**前端消费映射**：`frameIndex` → 时间轴刻度；`charts` → ECharts dataset；`keyEvents` → 时间轴标记 + 图表 `annotations`；`FullSnapshot.elements` → Three.js 元件位姿；`ValidationResult.errors` → 表单字段级红字提示。

### F3 AI Agent 对话与工具调用（核心，Python 侧）

**目标**：学生用自然语言"做实验"。v3.0 新增自由搭建工具集，Agent 能直接操作场景中的元件。

**输入**：学生文本指令（如"在左边加一个斜面"、"把方块质量改成3"）。

**输出**：Agent 回复 + 工具调用动作（增删改元件 / 调 Java 模拟）。

---

#### F3.1 RAG 子能力

**目标**：Agent 回答"为什么"有依据、不胡编。

**输入**：学生问题 + 当前实验上下文。

**输出**：带引用的回答（关联到教材片段）。

**流程**：问题 → 向量检索人教版高中物理教材相关片段（pdfplumber 提取文本 → 切片 → bge-m3 嵌入 → Chroma 检索 top-k） → 拼入提示词 → DeepSeek 生成 → 附引用。

**引用格式**：[人教版必修一 P45] 点击展开原文（300-500字），可折叠。

**图表处理**：教材图表提取为图片存 /data/kb/figures/，路径入库 KnowledgeChunk.metadata.figure_path，不入向量库仅入库文本。

**检索失败降级**：RAG 检索失败时用 Agent 自身知识生成，并标注"非教材引用"。

**知识库配置**：
- PDF 提取库：pdfplumber（表格处理强于 PyPDF2）
- 切片规则：按章节边界不重叠，章节内段落间重叠 100 字
- 嵌入模型：BAAI/bge-m3（DeepSeek 无 embedding API，本地部署）
- 检索 top-k：5，相似度阈值 0.7

---

#### F3.2 Agent 流程（意图分类五分支）

学生输入 → Agent 意图理解 → Tool Calling → 结果回传 → Agent 用自然语言解释

**意图分类**（LLM 单次调用，DeepSeek，max_tokens=200，附 few-shot 示例）：
- 加载模板 → 识别模板名 → 调 `run_simulation`（模板已含完整场景）
- 自由搭建 → 识别元件操作意图 → 调元件工具集（add/remove/move/rotate/modify/list/clear_element）
- 改参 → 识别目标元件 + 属性变更 → 调 `modify_element_property`
- 问原理 → 走 F3.1 RAG 子能力（不走工具）
- 查看历史 → 调 `list_experiment_records` 返回列表

**意图 → 工具映射表**（v3.1 新增，明确"建新场景"分两类）：

| 意图 | intent 值 | 对应工具 | 说明 |
|---|---|---|---|
| 加载模板 | `load_template` | `run_simulation` | 模板自带完整初始场景，无需逐个 add_element |
| 自由搭建 | `free_build` | `add_element` / `remove_element` / `move_element` / `rotate_element` / `modify_element_property` / `list_elements` / `clear_scene` | 学生从元件库自由组装，可多轮调用多个工具 |
| 改参 | `modify` | `modify_element_property` | 修改既有元件属性（与 free_build 的 modify_element_property 同工具，但意图明确为"改动当前场景某个属性"） |
| 问原理 | `question` | （不走工具，走 F3.1 RAG） | 知识检索 + 生成 |
| 查看历史 | `history` | `list_experiment_records` | 返回历史实验列表 |

**few-shot 示例**（v3.1 区分 load_template 与 free_build）：
- 加载模板："做个小车碰撞实验" → `intent=load_template, template=collision`
- 自由搭建："加一个小车" → `intent=free_build, action=add_element`
- 改参："把速度变3" → `intent=modify`
- 问原理："什么是动量守恒" → `intent=question`
- 查看历史："我昨天的实验呢" → `intent=history`

**边界规则**：含"做个/新建/来一个"+实验名=load_template；含"加/放/摆"+元件名=free_build；含"再做/再跑"+参数变更=modify。

**同工具不同意图的处理差异**（v3.2 新增，明确 modify_element_property 在两类意图下的 Agent 行为差异）：
- `free_build` 下的 `modify_element_property`：Agent 需先调 `list_elements` 确认目标元件存在，再执行修改
- `modify` 下的 `modify_element_property`：Agent 直接修改当前场景元件，若目标元件不明确则反问澄清
- 两者调用同一个工具，但前置校验和对话策略不同

**反问澄清**：参数歧义时反问澄清而非臆测。Agent 不能执行非白名单工具。

**意图分类 token 计入用户日预算**（与主调用共享 100K 上限）。

#### F3.5 LLM 失败/超时/限流降级

- DeepSeek 限流（429）：Agent 返回"系统繁忙，稍后重试"
- DeepSeek 超时：降级到"请稍后再试"
- DeepSeek 完全不可用：返回 503，前端提示降级

**token 预算**：每用户每日 100K tokens 硬上限（Redis 实时计数）。
- 请求前按 max_tokens=2000 预扣，响应后按实际用量回补
- 失败会话 token 计入系统账户（system_token_usage），用户预算不扣
- Redis 挂了降级放行+告警

---

#### F3.6 Token 计数与并发安全

- Redis INCRBY 原子操作，key=`token_usage:{user_id}:{date}`，TTL 25 小时
- Redis AOF appendfsync everysec，最多丢 1 秒
- Redis 重启后从 TokenUsage 表恢复当日已累计量
- 每日凌晨 2 点定时任务把 Redis 当日数据批量写入 TokenUsage 表

**跨服务事务补偿**：Java 入库失败时调 Python /agent/rollback 标记会话失败，前端区分"解析失败"（重试整个流程）和"保存失败"（重试保存）。

### F4 OCR 题目识别与半自动建场景

**目标**：拍照/上传题目 → 推荐元件组合 → 前端半透明预览 → 学生确认/微调 → 建场景。

**与 v2.6 关键变化**：从"自动建场景"改为"半自动模式"。Agent 推荐的元件组合在前端半透明预览，学生确认后才正式入场景，避免 Agent 误判直接覆盖学生已有场景。

---

#### F4.1 流程

1. 学生上传图片 → Java /api/ocr/upload 接收
2. Java 调 Python /ocr/recognize（传 base64）→ 返回 OCR 文字
3. Java 调 Python /agent/parse-question（传 ocrText）→ 返回 {simType, recommendedElements, confidence}
4. Java 校验推荐元件参数（调 Simulation.validate()）
5. 前端半透明预览推荐元件组合，学生可确认/微调
6. 学生确认 → Java 建场景入库 → 返回场景 ID

---

#### F4.2 /agent/parse-question 响应（v3.0 新增 recommendedElements）

```json
{
  "simType": "collision",
  "recommendedElements": [
    {"type": "cube", "position": {"x": -3, "y": 0}, "properties": {"mass": 2, "friction": 0}, "initialState": {"velocity": {"x": 5, "y": 0}}},
    {"type": "cube", "position": {"x": 3, "y": 0}, "properties": {"mass": 1, "friction": 0}, "initialState": {"velocity": {"x": -3, "y": 0}}}
  ],
  "confidence": 0.85,
  "fallbackHint": null
}
```

**降级**：
- OCR 识别失败/题型不匹配 → 返回 code=2004 + 提示"无法识别，建议手动建场景"
- Java validate 失败 → 返回结构化错误 {field, expected, actual, message} → Agent 反问学生
- 全流程超时 15 秒 → 返回"解析超时，建议手动建场景"
- 一图多题按题号正则分割（支持 1./1、/(1)/第一题/题1）
- 正则都匹配不到时整图当一个题处理
- 一图按一题处理时只返回主模拟类型，其余忽略

**OCR 图片预处理**：灰度化+二值化+倾斜校正（PaddleOCR 内置）。分辨率<300DPI 时提示重拍。

**Java 校验责任**：Python 返回的参数不可信，Java 建场景前必须调 Simulation.validate() 做白名单校验，是最后一道防线。

**参数 schema 一致**：Python 与 Java 共用同一份参数 JSON Schema（在 Simulation 实现类里定义），字段名严格一致。Java 用 Map<String, Object> 接收，validate 时做类型强转+校验。

### F6 实验报告自动生成

**目标**：学生做完实验即得报告草稿。

### F7 个性化学习路径

**目标**：Agent 按学生水平差异化引导。

**输入**：学生提问记录 + 实验历史。

**输出**：动态调整的引导策略（多解释/提挑战）。

**画像维度**（简化为 2 项，v2.6 删了"错误模式"项）：
- 知识掌握度（0-1）
- 操作熟练度（0-1）

**画像阈值**（v3.1 新增，可配置；与 F8 教师策略合成时使用）：
- 知识掌握度 > 0.7 → Agent 回答简洁（brief），可开启挑战题
- 知识掌握度 < 0.3 → Agent 回答详细（detailed）并关闭挑战
- 中间区间（0.3-0.7）→ 按教师策略执行（standard）
- 操作熟练度 > 0.7 → 减少操作提示（默认不弹元件库引导）
- 操作熟练度 < 0.3 → 增加操作提示（拖拽元件时高亮参数面板）
- 阈值通过 `teaching_strategy` 表的 `threshold_config` 字段覆盖，教师可调

**画像更新**：每 10 次提问后异步更新一次，不计入用户 token 预算（系统调用）。

**画像数据归属**学生本人，v1 画像维度限于"知识掌握度+操作熟练度"两项。

### F8 教师备课与教学策略配置

**目标**：教师备课，配置 Agent 对学生的引导风格。

**输入**：教师设定的策略（讲解详略、挑战强度、关注知识点）。

**输出**：策略生效到所教班级学生的 Agent。

**策略合成规则**（阈值可配置，默认掌握度>70 覆盖 brief，<30 覆盖 detailed 并关挑战）：
- 教师策略发布后对新开始的对话轮次生效
- 当前进行中的轮次用旧策略完成

**v1 教师不可见任何学生数据**，只能配策略+预览实验。v2 加班级后教师可见本班聚合统计（非个体对话）。

**预览示例问题**：3 条预设（"做个小车碰撞"/"把速度变3"/"什么是动量守恒"）。

**边界**：v1 策略是全局/班级级，不做精细到单个学生的教师配置。一个教师 v1 只一条全局策略（唯一约束 teacher_id+scope_type='global'）。

```

```

```
id, user_id, date, prompt_tokens, completion_tokens, total_tokens, created_at, updated_at
```

```
id, date, prompt_tokens, completion_tokens, total_tokens, reason, created_at, updated_at
```

```
id, record_id, action(start/pause/step/param_change/screenshot/export/report_generate),
```

```
id, actor_id, action, target_type, target_id, timestamp, ip
```

**响应格式**：`{code, message, data}`

#### WebSocket 接口

`ws://host/ws/simulation/{simId}?token={JWT}`

**握手鉴权**：HandshakeInterceptor 校验 token + simId 归属，失败关闭 4001，日志 token 替换 [REDACTED]。

**同 simId 单连接**：新连接挤掉旧连接（旧连接收 {type:"kicked"} 关闭）。

**服务端推送消息**：
- `{type:"frame", t, snapshot, snapshotType, dataTableIncrement, hasChart}`
- `{type:"keyEvent", t, label}`
- `{type:"ended", simId}`（前端切 RESTful 回放模式）
- `{type:"sync", currentT, isPaused, latestFrame}`（断线重连）
- `{type:"not_found"}`

**客户端控制消息**：
- `{action:"play"}` / `{action:"pause"}` / `{action:"step"}` / `{action:"seek", t}` / `{action:"sync"}` / `{action:"end"}`

**断线重连**：指数退避 1s/2s/4s 最多 3 次，重连发 sync，服务端按状态返回 sync/ended/not_found。
